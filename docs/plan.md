**Goal.** A nightly-refreshing local dashboard over clean sources, with a health system you'd trust before looking at a single chart. It opens from a desktop icon.

### Scope

- **Macro (FRED/ALFRED):** `GDP`, `GDPC1`, `CPIAUCSL`, all vintages.
- **Second price source:** used for reconciliation only (C12) and the opening-balance audit.
- **Health system:** checks C01–C14 (built: C01–C20), health CLI, `latest.md`, health page, fault-injection tests.
- **Dashboard:** Home, Health, and Charts pages. Desktop launcher. Nightly scheduled task.

### Acceptance criteria
1. From an empty data root, `uv run pharos refresh` backfills every watchlist series and both macro groups.
2. An immediate rerun adds zero rows to `serving/` and stays green (idempotent; `raw/` gains only that run's snapshot file).
3. `pharos health` is green, apart from documented expected states. ATVI shows as *ended*, not stale. If Yahoo no longer has ATVI history, that's reported explicitly as source-missing (warn). That's the survivorship finding, so it must be visible, not silent.

5. All 5 fault-injection tests pass. Each fault shows the right color and appears on the health page or heatmap.
6. Health page shows every element listed in design.md §7.
7. Charts page: overlay ≥3 series of mixed frequency (daily price + quarterly GDP + monthly CPI), change the dates, rebase, toggle log. Reloading the URL restores the chart.
8. Home opens to the watchlist chart with the status bar. It's never empty.
9. Desktop icon: cold start to data on screen < 10s; warm < 2s; opens in an Edge app window.
10. A nightly task is registered. A deliberately failed run shows on the dashboard and leaves serving data unchanged (D50; was 'raises a toast').

**Built** when 1–10 pass. **Done** after 7 consecutive green nightly runs. M2 can start once M1 is built.

## U: Universe (moved out of M2 by D128; kept as red-penned 2026-11-04, D109-D112. Steps 0 and 1 below were built under M2)

**Goal.** A survivorship-free, year-by-year list of every filer (CIK) that filed an annual report with the SEC: who joined, who left, who was there from the start. A filer is not yet a company: a company that re-registered under a new CIK appears as two filers until CIKs are linked, which is out of scope here (D54). A waterfall page narrows that population, one named step at a time, to the analysed set: what remains after every step, the last being domestic filers whose annual report that year carries XBRL financials. That is the set M4's cross-section page reads (D66). It refreshes nightly under the same health system as M1, and it becomes the expected set that M3's fundamentals are checked against.

### Scope (decided: D52-D70)
- **Top of the funnel (D54):** every CIK with an original annual report (form codes from `config/annual_forms.csv`, taken from the codes present in the full-index), 1993-11-29 to as-of. Complete from filing year 1997 (domestic) and 2002 (foreign); earlier years stored and flagged phase-in.
- **Membership (D55):** in for every calendar year from first to last annual report; empty years in between count, flagged; an exit is confirmed once a full calendar year passes with nothing filed.
- **Foreign filers (D53):** in, foreign status per filer-year from that year's form.
- **Events:** listing and exit forms from the full-index, by form type only (no filing text): 8-A12B / 8-A12G (registration), 25 / 25-NSE (delisting), 15-12B / 15-12G / 15-15D and 15F-12B / 15F-12G / 15F-15D (deregistration, domestic and foreign). Form codes come from the index, as for annual reports: 15-12B falls to 0 during 2022 while 15-12G rises (139 in 2021, 649 in 2023), so a typed list goes stale (C26). Exit reason = any exit form (25, 25-NSE, 15, 15F) filed after the filer's previous annual report (all of them when it filed only one), else `unknown` (D110). A reason that arrives after the exit is confirmed, or a gap year closed by a later filing, is a new vintage of that firm-year row (D59, D88).
- **Listing status (D65, D89, D111):** a labelled column on each firm-year, not a waterfall step: no form-only rule is accurate enough to drop on (D111). Exchange-listed in year Y, rebuilt from the forms: an 8-A12B on or before the end of Y with no later Form 25 / 25-NSE / 15-12B / 15F-12B before Y starts, and from 2022-06-17 on also 15-12G, since SEC stopped using the 15-12B code after 2022-06-16 (D89). A filer that never filed an 8-A12B but shows proof of a listing (a delisting form, or an exchange in the details snapshot) counts as listed from its first annual report to its first delisting form (D111). Delisting forms are filed per security, so a matured bond or expired warrant can end a listing wrongly; the label carries its measured accuracy. From the first details snapshot on, the snapshot's exchange field decides instead. Labelled approximate before 2006 (Form 25 counts: 0 before 2001, about 400-470 a year 2002-05, 1,400-2,400 from 2006) and blind to listings that began before EDGAR (no 8-A12B on file). The hole is measured, not guessed: acceptance #9.
- **Sources:** EDGAR full-index (`master.gz` per quarter), bulk `submissions.zip` (name, SIC, state, former names, current tickers and exchanges), `company_tickers_exchange.json` (current ticker to CIK).
- **Source groups (D81, D82):** the SEC universe is a second source group beside M1's prices + macro, not more required datasets on M1's run. Each group is judged complete, staged and gated on its own. A group that fails to load, stage or pass its gates is carried forward from the last good version, and the other groups publish. One served version still holds every group. A carried-forward group is yellow on its first missed run and red from its second in a row (D82). A flaky 1.57 GB SEC pull can then never freeze prices or macro (#73).

### Build order
- [x] 0. Source groups (D81, D82), built before any SEC code, on M1's data alone. Today's run contract is hard-wired for M1: `stage.py` requires exactly `DATASETS` (yf/prices, fred/observations, fred/series); `catalog.py` lists `RAW_DATASETS`; publish, staging, checks, board and C08 name observations and series_catalog directly (#73). Replace that with groups:
  - A group declares its raw datasets (required and reference), its staging SQL, its output tables and its checks. M1 becomes group `prices_macro` (yf/prices, fred/observations, fred/series required; tiingo/prices reference, D36/D37) with checks C01-C20. Each check's header gains a `group` field; a gate failure blocks only its own group. The Health page files a failing row under its check's group; inside `prices_macro` it keeps D42's column rule (series prefix, source column, ticker as Tiingo, else run), which holds only for that group's checks (D102)

  - Publish builds one version from the groups that passed, and copies each failed group's tables, and its `inputs/` files (D76), from the last version where that group published. ### Acceptance criteria
1. From an empty data root, `uv run pharos refresh` builds the universe and is green apart from two documented states: C27 warns 'no baseline' until step 7 records one, and the SEC group is red as never published (D83) on any run before its first publish. An immediate rerun adds zero rows to `serving/`. Health reports a check whose group is absent from the served version under that group's status (never published or carried forward, D81/D83), not as broken (D98).
2. Re-performance (step 7): from the spike's own files the pipeline reproduces the spike exactly: 48,209 CIKs, 319,098 firm-years, 10,568 gap years, and the per-year counts (e.g. 12,233 in 1997, 13,557 in 2002, 7,511 in 2026). On a fresh pull, every difference for filing dates through 2026-11-03 is listed and explained (for example, a filing SEC indexed after the spike's download); an unexplained difference fails.
3. Every check C21-C39 has a fault-injection test that shows it firing with the right color.
   For C27: drop one CIK from a closed year in staging -> warn naming that CIK; flip one CIK's listing status in a closed year -> warn naming the exchange-listed and analysed sets; accept the year -> green; a different change to the same year after the accept -> warns again; accept without a reason -> refused.
4. Every confirmed exit has a reason or `unknown`, and the share that is `unknown` is shown on the Universe page.
5. The waterfall foots for every year (C28: every firm-year in exactly one bucket), and each step names what it drops and how many.
6. The Universe page shows each population count per year (step 4), and every year's counts agree with the waterfall's buckets for that year. The overlay on GDP moved to M1.5 (D101).
7. The watchlist `cik` column is filled for all 18 names (#22), and the exchange list's difference from the universe is a named step or a documented expected state (#46).
8. Run time, measured from run_manifest: every nightly run with the universe in it finishes within 30 minutes. The first run, which lands the full filing history, is timed and recorded but not held to that limit. Basis (2026-11-04): M1 runs take 18-32 s; parsing all of submissions.zip took 53 s here; the 1.57 GB download is not yet timed.
9. Listing-status calibration (D65, D90): for the current year, the exchange-listed set rebuilt from the forms alone, computed for this comparison even though the stored current-year status comes from the details snapshot, is compared with the tickers file's exchange-listed set. Both differences are counted and shown on the Universe page: listed today with no 8-A12B on file is the size of the pre-EDGAR hole; rebuilt as listed but absent from the tickers file shows what the rule over-counts (debt-only listings, missed delistings). The spike's test (D111): of 3,955 filers on an exchange today with a 2025 10-K, the forms rule marks 77.1% listed; of 685 over-the-counter-only filers, 17.1%.

10. Source groups (D81, D82): with the SEC download made to fail, a run publishes prices + macro, and the SEC tables in the new version are identical to the previous version's. The manifest records the SEC group as carried forward with its reason and source run, and health shows it yellow (C35). A second failed run in a row turns it red (C36). From an empty data root with the SEC download failing, prices + macro still publish, SEC shows red as never published, and the Universe page says 'not yet published' (D83).
